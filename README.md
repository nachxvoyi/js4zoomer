# js4zoomer

Добро. Ты просишь «универсальное и ёмкое пособие» по голому JS — без воды, с упором на современный код‑стайл и тактику работы с ИИ. Дам его в виде мемо‑карты, которую можно держать открытой во время кода.

1. «Голый» JS — это твой фундамент

Фреймворки приходят и уходят, а Event Loop, замыкания и прототипы остаются.
Знание чистого JS делает тебя независимым от модных библиотек и позволяет читать любой код.

Что входит в ядро (ES6+):

· Переменные: let, const (никакого var!)
· Стрелочные функции () => {}
· Шаблонные строки ${}
· Деструктуризация объектов и массивов
· Spread / Rest (...)
· Модули (import / export)
· Промисы и async/await
· Классы (синтаксический сахар над прототипами)
· Map / Set / WeakMap / WeakSet

2. Современный код‑стайл (как пишут в 2026)

Ориентир — Airbnb Style Guide + Prettier (автоформатирование).
Правило Пример
const по умолчанию, let только для переприсвоения const PI = 3.14; let counter = 0;
Один const на объявление ✅ const a = 1; const b = 2; ❌ const a = 1, b = 2;
Стрелочные функции для колбэков [1,2].map(x => x * 2)
Фигурные скобки вокруг тела функции всегда if (x) { doSomething(); }
Пробелы после ключевых слов и вокруг операторов if (x === 1) { ... }
Кавычки — одинарные (') для строк, шаблонные для интерполяции const name = 'John';
Точка с запятой всегда (избегаем ASI‑костылей) const x = 5;
Именование: camelCase для переменных/функций, PascalCase для классов getUserData(), class UserController
Экспорты именованные, дефолтный — только если модуль один export const utils = ...; export default App;


Инструменты, которые следят за стилем:

· ESLint (с конфигом eslint-config-airbnb-base или standard)
· Prettier (автофикс при сохранении в VS Code)

3. Фундаментальные концепции (то, что обязан знать наизусть)

Без этого ты не сможешь понять ни фреймворк, ни чужой код, ни даже баги.

Концепция Кратко
Замыкание Функция, которая запоминает свою лексическую область видимости даже после выполнения внешней функции. Используется для инкапсуляции и фабрик.
Прототипное наследование Объекты наследуют свойства от других объектов через __proto__ (или Object.getPrototypeOf).
this Определяется в момент вызова функции. Правила: новый объект (new), явный bind/call/apply, контекст объекта, глобальный/undefined в строгом режиме.
Event Loop Как JS выполняет асинхронный код (микро‑ и макро‑задачи).
Hoisting Поднятие объявлений переменных (var) и функций в начало области видимости. С let/const — временная мёртвая зона.
Асинхронность Промисы, async/await — читай как синхронный код, но помни, что это сахар над промисами.
Замыкание и итераторы Генераторы (function*) и итерируемые протоколы (Symbol.iterator).

Что стоит уметь делать руками без ИИ:

· Написать свою реализацию Promise (хотя бы упрощённую)
· Реализовать глубокое клонирование объекта
· Написать функцию мемоизации
· Сделать debounce / throttle
· Работать с DOM: создавать элементы, добавлять слушатели, делегирование событий

4. Что можно смело делегировать ИИ (и что — нельзя)

✅ Можно (и даже нужно) делегировать:

Задача Почему
Генерация шаблонного кода CRUD, типовые функции валидации, преобразования данных.
Написание юнит‑тестов ИИ быстро пишет тесты для чистой логики (Jest/Vitest).
Рефакторинг Переписывание циклов в функциональный стиль, замена var на const/let.
Поиск синтаксических ошибок ESLint уже делает, но ИИ может объяснить причину.
Генерация JSDoc / комментариев Экономит время на документировании.
Перевод кода с другого языка Быстрое прототипирование.
Объяснение непонятного куска кода «Что делает эта функция?» — ИИ переформулирует.

❌ Что должен контролировать ТОЛЬКО ты:

Задача Почему
Архитектурные решения Выбор паттерна, структура модулей, разделение ответственности.
Асинхронные цепочки ИИ может запутаться в порядке выполнения, особенно с race-условиями.
Безопасность Валидация ввода, экранирование, защита от XSS/инъекций.
Оптимизация производительности ИИ не знает твоего бенчмарка, не сможет оценить нагрузку.
Работа с DOM и событиями Утечки памяти, обработка событий — требует понимания жизненного цикла.
Критические алгоритмы Сортировки, поиск, работа с большими данными — нужно самому анализировать сложность.

5. Как эффективно использовать AI в JS‑кодинге

Практические приёмы (на примере ChatGPT / Copilot)

1. Промпт по шаблону:
   «Напиши функцию на JS, которая принимает массив объектов и возвращает новый массив, сгруппированный по полю category, используя reduce. Напиши с JSDoc и тестом (Jest).»
2. Проси объяснить код — ИИ отлично пересказывает, но перепроверяй факты (он может галлюцинировать).
3. Используй AI как «дополнительный мозг» для поиска редких методов (например, как сделать глубокую заморозку объекта).
4. Не доверяй слепо — всегда запускай сгенерированный код в консоли и проверяй на краевых случаях.
5. Интеграция в IDE: Copilot / Codeium / Tabnine — они дают подсказки прямо при наборе, ускоряют ввод.

Золотое правило:

AI пишет код быстро, но ты должен понимать каждую строку, чтобы объяснить её на собеседовании и исправить, если AI ошибся.

---

Бонус: одна актуальная практика

Забудь про for циклы (почти). Используй:
.map(), .filter(), .reduce(), .forEach(), for...of.

Пример современного кода:

```js
// Старый стиль (не пиши так)
var arr = [1, 2, 3];
var doubled = [];
for (var i = 0; i < arr.length; i++) {
  doubled.push(arr[i] * 2);
}

// Новый стиль
const arr = [1, 2, 3];
const doubled = arr.map(x => x * 2);
```
